Quick start

  1. Copy the Customer folder to its permanent location on the monitored server.
  2. Run MiMonitoringService.exe as administrator.
  3. Enter the client name and a registered @millensys.com operator email.
  4. Create an activation request, send it to Millensys Support, and import the returned signed .milic license.
  5. Complete the guided setup for email, Windows Services, IIS pools, disks, and performance.
  6. Review the selections and choose Save and start MiMonitoringService.

License activation — click-by-click

This release uses a secure request-and-license file workflow for both online and offline monitored servers. Follow the steps below in order. The license is bound to the server that created the request.

A. Create the license request on the monitored server

  1. Copy the complete Customer folder to a permanent location on the monitored server.
  2. Open the Customer folder.
  3. Right-click MiMonitoringService.exe, then click Run as administrator.
  4. When Millensys license activation opens, click the Client name box and type the licensed company or client name.
  5. Click the Millensys operator box and type the registered @millensys.com email address.
  6. Keep This monitored server is offline checked. This checkbox is required in the current release, including when the server has internet access.
  7. Click Create offline request….
  8. Choose a folder that you can find easily, keep the .mirequest extension, and click Save.
  9. Click OK when the request-created message appears.
  10. Locate the saved file named similar to MiMonitoringService-SERVERNAME.mirequest.

B. If the monitored server is online

  1. From the monitored server, open the approved company email or file-transfer system.
  2. Create a message to Millensys Support.
  3. Click Attach, browse to the saved .mirequest file, select it, and click Open.
  4. Send the request to Millensys Support.
  5. When Support returns the signed .milic file, click Download or Save attachment.
  6. Save the .milic file in a known folder on the same monitored server.
  7. Continue with section E. Import the signed license.

C. If the monitored server is offline or isolated

  1. Insert an approved encrypted USB drive, or open the organization’s approved secure transfer location.
  2. Copy the saved .mirequest file from the monitored server to that approved transfer media or location.
  3. Remove or disconnect the media safely according to company policy.
  4. On an approved online workstation, open the transfer media or location.
  5. Copy the .mirequest file to the workstation.
  6. Open the approved company email or file-transfer system, attach the .mirequest file, and send it to Millensys Support.
  7. When Support returns the signed .milic file, save it on the online workstation.
  8. Copy the .milic file to the approved transfer media or location.
  9. Return to the same monitored server and copy the .milic file into a known local folder.
  10. Continue with section E. Import the signed license.

D. Millensys Support issues the license

  1. Open the private MillensysSupport-PRIVATE folder on the authorized support workstation.
  2. Right-click MiMonitoringService.LicenseGenerator.exe, then click Run as administrator.
  3. Click Open request…, select the customer’s .mirequest file, and click Open.
  4. Review the displayed client, operator, server, activation mode, and machine fingerprint.
  5. Click Send OTP. A branded verification email is sent to the registered operator, with a hidden registration reference copy to Millensys.
  6. Ask the operator for the six-digit verification code. The code expires after one hour.
  7. Type the six-digit code in the Email verification box, then click Verify.
  8. Confirm that Millensys email verified appears.
  9. Click the License expiration calendar and select the approved expiration date.
  10. Click Issue signed license….
  11. Choose the output folder, keep the .milic extension, and click Save.
  12. Return only the signed .milic file to the requester. Never send the private support folder, signing material, or SMTP configuration.

E. Import the signed license on the monitored server

  1. Return to the same monitored server that created the request.
  2. If the activation window is closed, open the Customer folder, right-click MiMonitoringService.exe, and click Run as administrator.
  3. In Millensys license activation, click Import signed license….
  4. Browse to the returned .milic file, select it, and click Open.
  5. Wait for Activation successful, confirm the displayed expiration date, then click OK.
  6. Complete each first-run setup page and click Next.
  7. On the Review page, click Save and start MiMonitoringService.
  8. Open Configuration → License to confirm the status, licensed client, server, license ID, and expiration date.
Do not delete operational licensing data: keep the Customer data folder during upgrades. It contains the machine-specific activation key and imported license. Do not copy a license to another server.

Renew the license

  1. Open MiMonitoringService.exe as administrator.
  2. Click Configuration, then click the License tab.
  3. Review the current expiration date.
  4. Click Renew or replace license….
  5. In the activation window, confirm the client name and Millensys operator email.
  6. Keep This monitored server is offline checked, then click Create offline request….
  7. Choose the save location, keep the .mirequest extension, and click Save.
  8. Repeat sections B or C, then D.
  9. Return to Configuration → License, click Renew or replace license…, then click Import signed license….
  10. Select the renewed .milic file and click Open. Existing settings, monitoring history, and operational data remain unchanged.

What works online and offline after activation

Online server: local monitoring, recovery actions, SMTP email and reports, plus HTTP/API checks when outbound access is permitted. Offline server: local services, IIS pools, disks, CPU, memory, schedules, recovery actions, dashboards, history, and CSV export. Email and external API checks require a reachable internal relay or approved network route.

Dashboard

Overview explains server health, active problems, protected items, and recent automatic actions. Double-click an issue to inspect its history.

Fair health score

The score starts at 100 and is reduced only by unresolved operational incidents. A service or IIS pool that remains down after its configured recovery retries reduces the score by 2%. Sustained unhealthy CPU or memory reduces it by 2%. When the same item fails three times within 15 minutes, a recurring incident reduces the score by 3%, even if the item later recovers. A stop that recovers during its retries, ordinary warnings and information, and a stopped monitoring agent do not reduce the score. Scores from 98–100 are Healthy, 95–97 require Attention, and below 95 is Critical.

Incidents dialog

  1. Open Overview.
  2. Click Incidents.
  3. Choose Today, This week, Last week, This month, or Custom.
  4. For Custom, select the From and To dates.
  5. Select an open incident and click Resolved after the engineer confirms it is handled. Its deduction is removed immediately and the action is recorded in Events & Logs.
Intentional stopped-state protection: if a selected Windows Service or IIS pool is already stopped when monitoring begins, MiMonitoringService treats that state as the administrator’s initial baseline. It does not reduce the score, send an incident email, or perform an automatic recovery action. After the target has been observed running or started at least once, a later stop becomes an active incident. This healthy baseline is saved and survives monitoring-agent restarts.

Windows Services and IIS Pools

Discover and search installed targets, select the required items, and independently enable or disable monitoring. Configure automatic recovery, retry escalation, API health checks, planned downtime, and daily, weekly, monthly, or interval schedules. Manual Start, Stop, and Recycle actions require confirmation and are audited.

Monitoring-only notifications

Clear the stopped-state recovery action to monitor a service or IIS pool without automatically changing it. If that target stops, MiMonitoringService sends one incident email containing its current status. It does not repeat the incident while the target remains unhealthy—even if the monitoring agent restarts. After an engineer restores the target, MiMonitoringService sends one recovery email and resets the incident, ready to notify again if a new outage occurs.

Related services restart chain

For a Windows Service, open Configure → Recovery and choose Discover services to select manually. Search and check multiple related services. During a restart, MiMonitoringService stops only selected related services that are currently running, restarts the main service, then restores those related services. Every step is audited.

Disk and performance monitoring

Monitor every detected drive or selected drives using free-space thresholds. CPU and memory alerts require sustained threshold breaches, preventing noise from short spikes. A recovery message is sent only after health returns.

Performance intelligence

The dedicated Performance page shows live server CPU and memory, current top processes, Windows Services and IIS pools consuming resources, a 24-hour trend, and a peak timeline with the likely root cause recorded at each sample.

Email and reports

The configured sender name is MiMonitoringService. Subjects use Client name | notification title. Messages include server name and MAC address. To and CC recipients are configurable. Daily and monthly reports use the same branded HTML layout.

Client analytics report

  1. Open Reports.
  2. Choose This month or Custom duration.
  3. For a custom duration, select the start and end dates.
  4. Click Generate preview to review the eight section results.
  5. Click Export PDF… for a client-ready fixed report, or Export Word… for an editable report.
  6. Click Queue PDF email to send the selected duration to the configured report recipients.

The report contains duration overview; server health, database growth, and backup charts; database health and daily backup validation; incidents and warnings; Windows Service stability; IIS pool stability; business impact; and recommended next actions. Open Configuration → Reports & Email and enable Attach the full eight-section analytics PDF to the monthly report for automatic monthly delivery.

Credential safety: SMTP app passwords are protected with Windows DPAPI for this machine. They are never displayed again or stored as readable configuration.

SQL backup monitoring

  1. Open Assurance.
  2. Open the SQL Backups tab.
  3. Click + Add backup rule.
  4. Enter a rule name.
  5. Click Browse folder… to monitor a folder, or Browse file… for one specific backup file.
  6. Enter a filename pattern such as *.bak and an optional keyword such as ERP.
  7. Set Maximum calendar age: 0 requires today’s backup, 1 accepts today or yesterday, and so on.
  8. Select the daily check time.
  9. Choose whether to email when found, missing, or recovered.
  10. Click Save rule.

At the scheduled time the service selects the newest matching file and compares its modified calendar date with the configured server time zone. A missing, inaccessible, or old backup creates a −2% health incident. A valid later backup resolves it automatically. Multiple databases or file patterns are supported by creating multiple rules.

Network paths: a UNC path such as \\BackupServer\SQL must be accessible by the Windows account running MiMonitoringService. LocalSystem normally does not inherit the signed-in user’s network permissions.

File integrity monitoring

  1. Open Assurance → File Integrity.
  2. Click + Add file monitor.
  3. Enter a monitor name, click Browse…, and select the important file.
  4. Click Save monitor.

The accepted baseline includes path, name, extension, size, creation time, modified time, and SHA-256 content hash. Creation, deletion, content modification, rename, and extension changes generate one component-change email and appear in Changes.

Implemented component baselines

Every enabled monitored Windows Service and IIS pool is snapshotted automatically. A Windows Service baseline includes service name, display name, executable path, executable creation and modification time, SHA-256, file/product version, publisher, startup type, service account, and description. This detects deletion, reinstallation, executable replacement, and same-name replacement where details differ.

An IIS pool baseline contains its advanced configuration plus assigned sites, applications, virtual directories, application-pool assignments, and physical paths. It detects advanced-setting changes, child applications added or removed, pool reassignment, and physical-path changes. Password, secret, token, and credential fields are excluded from snapshots.

Review component changes

  1. Click Changes on Overview, or open Assurance → Component Changes and click Open Changes….
  2. Filter by Today, This week, Last week, This month, or a Custom date range.
  3. Optionally filter by Windows Service, IIS Pool, or File.
  4. Review the item, clear setting name, old value, new value, and detection timestamp. For example, IIS displays Enable 32-Bit Applications instead of an internal XML path.
  5. Click Refresh now to request an immediate table refresh. The open dialog also refreshes automatically every 10 seconds; component snapshots run every 60 seconds.
  6. Click Resolved to close only the selected change, or click Accept current baseline after verifying the implemented component. Accepting a baseline closes all open changes for that component and records the engineer’s action.

Monitoring service

Configuration → Agent Service provides Install, Start, Stop, and Remove safely. Removal stops the service first. The GUI and service executables are self-contained; Python is not required on the target server.

Single instance and system tray

Only one MiMonitoringService console can run at a time. Closing the window can hide it in the Windows system tray while the monitoring service continues. The tray menu can reopen the console, start or stop the monitoring service, or exit the console. Tray behavior is configurable under Configuration → Monitoring.

Events, logs, and diagnostics

Events & Logs shows normal operating history and supports filtering and CSV export. Enable debug mode only while diagnosing a problem because it produces more detail. Configuration changes and automated actions are always recorded.

Troubleshooting

License cannot be imported

Confirm the file is a signed .milic issued from this server’s latest request, the license has not expired, and the Customer data folder still contains the original activation key. If the machine was rebuilt or its identity changed, create a new request.

No email

Verify To recipients, SMTP connectivity, firewall or relay access, and the email queue status. Use the SMTP test button after saving. A fully isolated server cannot send internet email without an approved reachable relay.

IIS pools not detected

Confirm IIS is installed and the application is running elevated. Refresh discovery after IIS changes.

Service not running

Open Configuration → Agent Service, install if needed, then start it. Review Events & Logs and data\logs\guardian.log for the recorded error.
